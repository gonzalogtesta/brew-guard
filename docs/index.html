brew-guard

Homebrew, but with a security policy and without the telemetry.

I like Homebrew and I don't want to replace it. What bothers me is that it installs and upgrades whatever is out there, minutes after release, and nobody checks if it is any good. brew-guard sits next to brew and applies rules you set. It never patches Homebrew's files.

Early development, latest release is v0.3.0 (unsigned). With the brew link in your PATH, brew install, reinstall and upgrade go through your policy first. A real install through the wrapper on macOS, and casks, are not tested yet. Don't count on it to protect you today.

What it does today

  • Refuses versions younger than N days (default 12), with per-package exceptions that expire.
  • Tap allowlist. Third party taps are flagged for review.
  • Finds the release date from the homebrew-core / homebrew-cask commit history, not from a bottle rebuild.
  • Checks that Homebrew analytics are off (doctor) and sets them for you (harden --apply): Homebrew's own brew.env, your shell files and the analytics opt-out, with a backup and harden --undo to go back.
  • Checks everything an install would bring, not only the package you name. One young dependency blocks the install, and so does a dependency that brew would upgrade to a young version.
  • Works as a brew wrapper: install, reinstall and upgrade run only after the check passes, read-only commands pass through, the rest is refused.
  • Prints what runs at install time (post-install steps, services, installers) so you can see it before it happens.
  • repair detects an altered Homebrew folder and can reset it to an official release.
  • Writes an audit log of every decision.

Policy

min_age_days = 12
mode = "block"            # or "warn"
allowed_taps = ["homebrew/core", "homebrew/cask"]
block_telemetry = true

[[exception]]
package = "jq"
reason = "needed for a security fix"
expires = 2026-12-01

The same settings work as JSON or plain text. Unknown keys are an error, so a typo can't quietly turn a rule off.

Try it

git clone https://github.com/gonzalogtesta/brew-guard
cd brew-guard
go run ./cmd/brew-guard check jq
go run ./cmd/brew-guard brew install jq

The second command installs jq only if the check passes. To make brew itself run it, see brew-guard shim install in the README.

You need the Go version pinned in go.mod.

Network

No telemetry. The only host brew-guard talks to is api.github.com, read-only, to get the commit history of a formula or cask. An optional token is only sent to that host.

Dependencies

None, standard library only. Versions are pinned, see PINNED-VERSIONS.md.

Limits

It lowers risk, it doesn't prove a package is safe. It won't help if Homebrew's own infrastructure is compromised, if the malicious code is old, or if malware already runs as your user.
